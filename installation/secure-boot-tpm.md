Это критически важный этап. Сочетание Secure Boot и TPM 2.0 превращает систему в настоящую «крепость»: ядро нельзя подменить, параметры загрузки нельзя изменить, а расшифровка диска происходит автоматически только в том случае, если цепочка доверия не нарушена.

# Безопасность: Secure Boot и TPM 2.0
Этот раздел описывает процесс настройки доверенной загрузки (Verified Boot) с использованием собственных ключей и аппаратного модуля TPM для автоматической расшифровки раздела LUKS.
## 1. Подготовка UEFI (Setup Mode)
Перед генерацией ключей необходимо перевести прошивку материнской платы в режим, позволяющий записывать собственные ключи.
 1. Зайдите в BIOS/UEFI (обычно клавиша F2 или Del).
 2. Перейдите в раздел Security -> Secure Boot.
 3. Найдите опцию удаления стандартных ключей (Microsoft) или перевода в Setup Mode (часто называется «Reset to Setup Mode» или «Custom Mode»).
 4. Убедитесь, что Secure Boot включен, но находится в режиме User Mode: Setup.
 5. Сохраните настройки и загрузитесь в Gentoo.
## 2. Управление ключами через sbctl
Для работы с ключами используется утилита app-crypt/sbctl. Она автоматизирует создание и запись ключей в NVRAM материнской платы.
### Создание ключей
# Создание собственной иерархии ключей
doas sbctl create-keys

### Запись ключей в прошивку
Записываем свои ключи (и, при необходимости, ключи Microsoft для поддержки стороннего оборудования/Option ROM).
# Запись ключей в UEFI
doas sbctl enroll-keys -m

*Флаг -m (Microsoft) рекомендуется для сохранения совместимости с видеокартами и прошивками других устройств.*
### Подпись UKI
После записи ключей убедитесь, что ваш образ UKI (созданный через Dracut) подписан. В нашем конфиге 90-uki.conf для Dracut это происходит автоматически, но можно проверить вручную:
doas sbctl status
doas sbctl verify

## 3. Привязка LUKS к TPM 2.0 (systemd-cryptenroll)
Вместо ввода пароля при каждой загрузке мы используем systemd-cryptenroll для привязки ключа к регистрам PCR (Platform Configuration Registers) модуля TPM.
### Используемые PCR:
 * PCR 0: Контроль прошивки (Core System Firmware).
 * PCR 7: Контроль состояния Secure Boot.
### Процесс привязки
Найдите ваш зашифрованный раздел (например, /dev/nvme0n1p3) и выполните привязку:
# Привязка раздела к TPM 2.0 с проверкой PCR 0 и 7
doas systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=0+7 /dev/nvme0n1p3

> Важно: После выполнения этой команды при следующей загрузке systemd-executor в initramfs (который мы добавили в Dracut) автоматически обратится к TPM, проверит, что прошивка и Secure Boot не менялись, и отдаст ключ для расшифровки.
> 
## 4. Финализация
 1. Перезагрузитесь в BIOS.
 2. Убедитесь, что Secure Boot активен и перешел из Setup Mode в User Mode (Deployed).
 3. Загрузите систему. Теперь ввод пароля от LUKS не потребуется, если загрузка проходит в штатном режиме.
