## Result / Trust model

Что получится после настройки:

- **Secure Boot** — прошивка проверяет подписи доверенной загрузочной
  цепочки: неподписанный или подменённый компонент не пройдёт проверку.
- **TPM2** — LUKS-раздел разблокируется автоматически, пока выбранная
  PCR-policy соответствует фактическому measured state: если измеряемое
  состояние на момент загрузки не совпало с состоянием на момент зачисления
  токена, вместо авторазблокировки система запросит пароль LUKS.
- **Пароль LUKS остаётся recovery path**: TPM-токен добавляет удобство, но
  не заменяет пароль и не удаляет парольный слот.

Уровень защиты определяется выбранным набором PCR и конфигурацией
загрузочной цепочки, а не самим фактом включения Secure Boot.

## Applicability

- x86 UEFI, корень на LUKS2;
- systemd в initramfs с tpm2-tss (модули Dracut из
  [UKI-руководства](../systemd-uki-setup/));
- ключи и подпись образов — sbctl; UKI подписывается при сборке.

## Before you begin

До `sbctl create-keys`, `sbctl enroll-keys` и зачисления TPM-токена
убедитесь, что есть:

- рабочий пароль LUKS — вы должны уметь разблокировать раздел вручную;
- recovery/live носитель на случай проблем с загрузкой;
- понимание текущего состояния Secure Boot (посмотреть — `doas sbctl status`);
- существующий подписанный boot path и возможность вернуться к нему
  (fallback-UKI, см. [Rollback в UKI-руководстве](../systemd-uki-setup/#rollback--fallback));
- не очищайте TPM и key databases прошивки без отдельной причины.

## 1. Secure Boot

Ключами управляет `app-crypt/sbctl`: она создаёт собственную иерархию ключей
и записывает её в NVRAM материнской платы.

### Prepare firmware (Setup Mode)

Перед генерацией ключей необходимо перевести прошивку в режим, позволяющий
записывать собственные ключи.

1. Зайдите в BIOS/UEFI (обычно клавиша F2 или Del).
2. Перейдите в раздел Security -> Secure Boot.
3. Найдите опцию удаления стандартных ключей (Microsoft) или перевода в Setup Mode (часто называется "Reset to Setup Mode" или "Custom Mode").
4. Убедитесь, что Secure Boot включен, но находится в режиме User Mode: Setup.
5. Сохраните настройки и загрузитесь в Gentoo.

### Create keys

```bash
# Создание собственной иерархии ключей
doas sbctl create-keys
```

### Enroll keys

Записываем свои ключи (и, при необходимости, ключи Microsoft для поддержки
стороннего оборудования/Option ROM).

```bash
# Запись ключей в UEFI
doas sbctl enroll-keys -m
```

> **Примечание**: `-m` дополнительно записывает ключи Microsoft. Это выбор
> совместимости с прошивками и option ROM сторонних устройств (например,
> видеокарт), а не обязательный элемент процедуры: если такого оборудования
> нет, можно записать только собственные ключи.

### Verify signed UKI

После записи ключей убедитесь, что ваш образ UKI подписан. В конфигурации
Dracut из [UKI-руководства](../systemd-uki-setup/) подпись происходит
автоматически (`uefi_secureboot_cert/key` в `90-uki.conf`), но проверить
можно вручную:

```bash
doas sbctl status
doas sbctl verify
```

## 2. TPM2 и LUKS: автоматическая разблокировка

### Модель: слоты, токен, политика

```text
password slot = recovery
TPM token = convenience / policy-bound auto-unlock
PCR selection = policy decision
```

- **password slot** — парольный слот LUKS остаётся: это способ открыть
  раздел, если TPM недоступен или PCR не совпали;
- **TPM token** — ключ, зачисляемый через `systemd-cryptenroll` и
  отпираемый автоматически только при совпадении выбранных PCR;
- **PCR selection** — набор PCR, к значениям которых привязывается
  TPM-policy. Эти регистры расширяются разными компонентами загрузочной
  цепочки: firmware, boot loader, systemd-stub и другими компонентами в
  зависимости от PCR. Выбор набора — политика: чем строже, тем меньше
  сценариев, в которых анлок сработает сам.

### Как выбирают PCR

Ключ, зачисленный через `systemd-cryptenroll`, отпирается автоматически,
только если значения выбранных PCR в момент загрузки совпали с моментом
зачисления. Часто используемые регистры:

- **PCR 0** — контроль прошивки (Core System Firmware);
- **PCR 2** — option ROM;
- **PCR 4** — загрузчик (для UKI — сам образ);
- **PCR 7** — состояние Secure Boot: политика, ключи, сертификаты;
- **PCR 8/12** — командная строка ядра и параметры загрузки.

Чем шире набор, тем строже политика — и тем чаще придётся перезачислять
токен: любое изменение измеряемого содержимого (обновление BIOS, перезапись
ключей Secure Boot, пересборка UKI со сменой cmdline) делает его
недействительным.

Распространённый «строгий» вариант — `0+7`: разблокировка связывается и с
прошивкой, и с состоянием Secure Boot.

> ⚠️ **Важный нюанс**: не предполагайте фактический measurement path конкретной машины только по ожидаемой схеме. Если поведение PCR отличается от ожидаемого, сравните значения и TPM event log до и после контролируемого изменения (слепки: `tpm2_pcrread sha256:<N>`). Как находить фактический состав — в [troubleshooting: TPM2-анлок после пересборки UKI](../../troubleshooting/luks-tpm2-unlock-after-uki-rebuild/).

### Привязка (systemd-cryptenroll)

Найдите ваш зашифрованный раздел (например, `/dev/nvme0n1p3`) и выполните
привязку с выбранным набором PCR:

```bash
# Общий пример: PCR 0 + 7
doas systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=0+7 /dev/nvme0n1p3

# Набор, проверенный на эталонной машине asus-b5402: только PCR 7
doas systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=7 /dev/nvme0n1p3
```

> **Важно**: зачисление TPM-токена не удаляет парольный слот — пароль остаётся способом открыть раздел, если TPM сломается или PCR изменятся. После зачисления при следующей загрузке `systemd-cryptsetup` в initramfs (добавленном в Dracut) обратится к TPM, сверит выбранные PCR и отдаст ключ для расшифровки.

### Эталонная машина: ASUS B5402

Политика и наблюдения конкретной машины — не универсальная рекомендация.
Хронология, диагностика и процедура перезачисления — в
[troubleshooting: TPM2-анлок после пересборки UKI](../../troubleshooting/luks-tpm2-unlock-after-uki-rebuild/).

- **Политика машины**: набор из одного **PCR 7**; токен перезачислен и
  проверен реальной загрузкой 2026-09-14.
- **Наблюдение (2026-09-14)**: смена cmdline совпала с PCR-mismatch и
  потерей авторазблокировки; повторное зачисление восстановило её. В
  марте/апреле были сбои анлока, причина которых не исследовалась.
- **Гипотеза (не доказана)**: одно из изменений загрузочной цепочки влияет
  и на значение PCR 7. Точный measurement path прошивки не подтверждён:
  прямой before/after-замер `tpm2_pcrread sha256:7` для смены cmdline не
  выполнялся.
- **Состояние на 2026-09-22**: `sbctl status` — Setup Mode Disabled, Secure
  Boot Enabled, vendor keys microsoft; `sbctl verify` — все присутствующие
  в ESP образы подписаны (включая текущий UKI и systemd-boot).

## Финализация

1. Перезагрузитесь в BIOS.
2. Убедитесь, что Secure Boot активен и перешел из Setup Mode в User Mode (Deployed).
3. Загрузите систему. Теперь ввод пароля от LUKS не потребуется, если загрузка проходит в штатном режиме.

## Verification

Проверки выполняются вручную по факту после настройки; как тест во время
настройки их запускать не нужно.

1. **Secure Boot**: `doas sbctl status` — Secure Boot Enabled, Setup Mode
   Disabled (User Mode).
2. **Подпись UKI**: `doas sbctl verify` — все образы в ESP подписаны.
3. **TPM-токен**: `doas cryptsetup luksDump /dev/nvme0n1p3 | grep -A20 '^Tokens:'`
   (подставьте свой LUKS-раздел) — в блоке `Tokens:` есть токен с
   `tpm2-hash-pcrs`.
4. **Успешная перезагрузка**: система загрузилась без запроса пароля LUKS;
   единственная честная проверка авторазблокировки — реальная загрузка.
5. **Recovery-пароль остаётся рабочим**: парольный слот виден в `luksDump`
   и не удаляется зачислением; фактически пароль запрашивается и принимается,
   когда PCR не совпали.

## Troubleshooting / Recovery

- Авторазблокировка пропала после пересборки UKI или смены cmdline —
  диагностика (PCR-слепки, журнал `systemd-cryptsetup`) и перезачисление
  токена: [troubleshooting: TPM2-анлок после пересборки UKI](../../troubleshooting/luks-tpm2-unlock-after-uki-rebuild/).
- Система не загружается после смены ключей или образа — fallback-UKI в
  меню systemd-boot и recovery-носитель; порядок отката —
  [Rollback в UKI-руководстве](../systemd-uki-setup/#rollback--fallback).
