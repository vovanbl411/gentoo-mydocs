`doas` используется для выполнения команд с повышенными привилегиями и
предоставляет компактную конфигурацию. Его policy задаётся в `/etc/doas.conf`.
Руководство показывает базовый пример правил и основные команды. Фактическая
policy ASUS B5402 находится в
[системном разделе](../../systems/asus-b5402/security/doas/); точная системная
конфигурация здесь не дублируется.

## 1. Перед изменением

Ошибка в `/etc/doas.conf` может лишить пользователя ожидаемого способа
повышения привилегий. До изменения подготовь рабочий root/recovery path и
сохрани предыдущую конфигурацию. Placeholders вроде `<username>` нужно
заменить реальными значениями.

## 2. Конфигурация

Файл: `/etc/doas.conf`

Ниже приведён пример policy, а не точная опубликованная конфигурация ASUS
B5402.

```conf
# wheel: требуется аутентификация, временный persist и сохранение окружения
permit persist keepenv :wheel
```

Формат правила:

```text
permit|deny [options] identity [as target] [cmd command [args ...]]
```

Семантика, которую важно учитывать:

- Результат определяет **последнее совпавшее правило** (last matching rule),
  а не первое; опции нескольких совпавших правил не объединяются. Если нужны
  одновременно `persist` и `keepenv`, они должны стоять в одном правиле — как
  в примере выше.
- `persist` — после успешной аутентификации повторная аутентификация
  некоторое время не требуется; накопленное состояние сбрасывается `doas -L`.
- `keepenv` — переменные окружения пользователя не очищаются.
- `nopass` — совпавшее правило выполняется без аутентификации.
- Для `cmd` предпочтителен absolute path.
- Порядок правил важен: более позднее специфичное правило перекрывает более
  раннее общее именно для совпавших команд.

### Optional: passwordless для конкретной команды

Разрешить одной команде выполняться без аутентификации — отдельная осознанная
policy. Она не нужна для обычной работы doas; `persist` её не заменяет:
passwordless — это только `nopass`.

```conf
# Optional example: snapper конкретному пользователю без аутентификации
permit nopass <username> as root cmd /usr/bin/snapper
```

Более позднее command-specific правило перекрывает более общее правило для
совпавшей команды. Это иллюстрация возможной policy, а не утверждение о
фактической конфигурации ASUS B5402.

### Gentoo: сборка с поддержкой persist

В Gentoo поддержка `persist` включается USE-флагом:

```text
app-admin/doas[persist]
```

Без этого флага опция `persist` в правилах не поддерживается.

## 3. Основные команды

| Команда | Описание |
|---------|----------|
| `doas <command>` | Выполнить команду от root |
| `doas -s` | Запустить shell от root |
| `doas -u <user> <command>` | Выполнить команду от конкретного пользователя |

## 4. Проверка

Синтаксис конфигурации проверяется до применения, если установленная версия
поддерживает config-check:

```bash
doas -C /etc/doas.conf
```

Флаг `-C` только разбирает и проверяет конфигурацию и не выполняет команду
(точную семантику см. в `man doas` своей версии). После изменения проверь,
что обычная разрешённая команда выполняется. Затем отдельно проверь
command-specific rule и убедись, что лишние права не появились. Этот документ
не фиксирует результаты такой проверки.

## 5. Преимущества doas

- Легковесный и простой
- Меньше зависимостей, чем sudo
- Легче в настройке для базовых задач

## 6. Rollback и восстановление

Сохрани предыдущий рабочий `/etc/doas.conf`. Если новая policy не работает,
верни прежнюю конфигурацию через заранее подготовленный root/recovery access.
