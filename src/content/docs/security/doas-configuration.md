`doas` используется для выполнения команд с повышенными привилегиями и
предоставляет компактную конфигурацию. Его policy задаётся в `/etc/doas.conf`.
Руководство показывает базовый пример правил и основные команды. Фактическая
policy ASUS B5402 находится в
[системном разделе](../systems/asus-b5402/security/doas.md); точная системная
конфигурация здесь не дублируется.

## 1. Перед изменением

Ошибка в `/etc/doas.conf` может лишить пользователя ожидаемого способа
повышения привилегий. До изменения подготовь рабочий root/recovery path и
сохрани предыдущую конфигурацию. Placeholders вроде `<username>` нужно
заменить реальными значениями.

## 2. Конфигурация

Файл: `/etc/doas.conf`

Ниже приведён пример policy, а не точная опубликованная конфигурация ASUS
B5402.

```conf
# Разрешить пользователю выполнять команды от root с сохранением пароля на время сессии
permit persist :wheel

# Сохранять переменные окружения для конкретного пользователя
permit keepenv <username>

# Разрешить выполнение snapper без ввода пароля (для снапшотов)
permit persist :wheel as root cmd snapper
```

## 3. Основные команды

| Команда | Описание |
|---------|----------|
| `doas <command>` | Выполнить команду от root |
| `doas -s` | Запустить shell от root |
| `doas -u <user> <command>` | Выполнить команду от конкретного пользователя |

## 4. Проверка

После изменения проверь, что обычная разрешённая команда выполняется. Затем
отдельно проверь command-specific rule и убедись, что лишние права не
появились. Этот документ не фиксирует результаты такой проверки.

## 5. Преимущества doas

- Легковесный и простой
- Меньше зависимостей, чем sudo
- Легче в настройке для базовых задач

## 6. Rollback и восстановление

Сохрани предыдущий рабочий `/etc/doas.conf`. Если новая policy не работает,
верни прежнюю конфигурацию через заранее подготовленный root/recovery access.
