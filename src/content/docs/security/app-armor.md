AppArmor — система Mandatory Access Control (MAC), которая ограничивает
приложения профилями с разрешениями на доступ к файлам, возможностям и другим
ресурсам. Это руководство показывает базовую настройку AppArmor, режимы и
управление профилями, создание своего профиля и диагностику нарушений.

Это общее руководство, оно не описывает подтверждённое состояние ASUS B5402.
Требования к ядру и параметры загрузки ниже — общие описания и примеры, а не
зафиксированная конфигурация эталонной системы.

## 1. Перед включением

До изменения системы нужны:

- поддержка AppArmor и audit в ядре;
- userspace-пакеты AppArmor;
- AppArmor в списке LSM, активных в ядре;
- понимание того, что профиль в режиме Enforce может блокировать действия
  приложения, если нужные разрешения не описаны.

### Поддержка в ядре

Для работы AppArmor нужны `CONFIG_SECURITY_APPARMOR=y` (сам LSM) и
`CONFIG_AUDIT=y` (логирование нарушений). Существующий пример конфигурации
ядра из документа:

```conf
CONFIG_SECURITY_APPARMOR=y
CONFIG_SECURITY_APPARMOR_BOOTPARAM_VALUE=1
CONFIG_AUDIT=y
```

Одного включения AppArmor в ядре мало: он должен присутствовать в списке
LSM, которые ядро активирует при загрузке. Предпочтительный способ — задать
корректный `CONFIG_LSM` в конфигурации ядра, включив AppArmor в список.

### Параметры загрузки: `lsm=` и `security=`

Параметр `lsm=` — это override полного списка LSM: он задаёт и состав, и
порядок всех активируемых LSM и переопределяет `CONFIG_LSM`. Если передать в
`lsm=` короткий фиксированный список, из активной конфигурации пропадут
другие включённые LSM — например `lockdown`, `yama` или `integrity`.
Универсальной строки `lsm=...` для всех систем нет, поэтому не используй её
как baseline. Если `lsm=` действительно нужен, сначала определи текущий
список LSM, сохрани все нужные LSM и их порядок и только затем добавь или
перемести в нём AppArmor.

Параметр `security=apparmor` выбирает AppArmor как major security module; он
нужен, только если этого требует конфигурация ядра. Если задан `lsm=`,
приоритет у `lsm=`.

Проверить список активных LSM:

```bash
cat /sys/kernel/security/lsm
```

Это общая команда проверки; её вывод для ASUS B5402 в этом документе не
зафиксирован.

## 2. Установка и включение

Установи userspace-пакеты:

```bash
emerge -av sys-apps/apparmor sys-apps/apparmor-utils
```

Включи и запусти сервис:

```bash
doas systemctl enable apparmor
doas systemctl start apparmor
```

## 3. Режимы и управление профилями

Для базового workflow этого руководства используются два основных режима:

- **Enforce** — профиль применяется: нарушения policy блокируются;
- **Complain** — нарушения policy разрешаются, но логируются; режим для
  разработки профиля и диагностики.

AppArmor поддерживает и дополнительные profile modes, которые здесь не
рассматриваются.

Disable — не режим загруженного профиля. `aa-disable <profile>` выгружает
профиль и предотвращает его автоматическую загрузку — это управление
профилем.

### Основные команды

| Команда | Описание |
|---------|----------|
| `apparmor_status` | Показать статус AppArmor |
| `aa-status` | Краткий статус профилей |
| `aa-complain <profile>` | Перевести профиль в режим complain |
| `aa-enforce <profile>` | Перевести профиль в режим enforce |
| `aa-disable <profile>` | Выгрузить профиль и отключить его автозагрузку |
| `apparmor_parser -r /path/to/profile` | Перезагрузить профиль |

Перед переводом нового или изменённого профиля в Enforce проверь поведение
приложения в Complain: так потенциально недостающие разрешения сначала
появятся в журнале, а не заблокируют приложение.

## 4. Создание и обновление профиля

### 4.1. Генерация профиля

Основной workflow для нового приложения начинается с `aa-genprof`:

```bash
doas aa-genprof /usr/bin/application
```

`aa-genprof` сам создаёт профиль (через `aa-autodep`, если его ещё нет),
переводит его в complain, предлагает запустить приложение и выполнить
типичные действия, сканирует журнал, обновляет правила, а по команде Finish
переводит созданные профили в enforce.

### 4.2. Обучение профиля

Пока `aa-genprof` запущен, открой другой терминал или сессию, запусти
приложение и выполни его реальные сценарии работы. Вернись к wizard,
добавь накопившиеся события через Scan и повторяй до покрытия сценариев,
затем заверши через Finish.

### 4.3. Дообучение существующего профиля

Если профиль уже существует и его нужно вручную продолжить обучать и
уточнять, переведи его в complain (`aa-complain`), выполни рабочие сценарии
приложения и собери недостающие правила из журнала через `aa-logprof`.
Вручную отредактированный профиль перезагрузи командой
`apparmor_parser -r /path/to/profile` из таблицы выше; режим меняется через
`aa-complain` и `aa-enforce`.

## 5. Пример профиля

Ниже — упрощённый пример типовых видов правил. Это не рабочий профиль
реального приложения.

```apparmor
#include <tunables/global>
/usr/bin/example {
  #include <abstractions/base>

  # Файлы
  /etc/example/** r,
  /var/lib/example/ rw,
  /home/*/.config/example/** rw,

  # Возможности
  capability net_bind_service,

  # Сеть
  network inet stream,
}
```

## 6. Утилиты

- **aa-genprof** — создание и обучение нового профиля;
- **aa-logprof** — обновление существующего профиля по событиям
  audit-журнала;
- **aa-notify** — уведомления о событиях AppArmor.

## 7. Проверка и диагностика

Состояние AppArmor и загруженных профилей показывают `apparmor_status` и
`aa-status` из таблицы основных команд. Для диагностики нарушений и проверки
конкретного профиля используй существующие примеры:

```bash
# Просмотр логов нарушений
dmesg | grep -i apparmor

# Или через journalctl
journalctl -b | grep -i apparmor

# Проверка синтаксиса профиля без загрузки в ядро
apparmor_parser -d /etc/apparmor.d/profile.name
```

`apparmor_parser -d` проверяет, как parser разбирает профиль, и не загружает
его; это не анализ runtime-нарушений — их ищи в журнале командами выше. Для
подробного dump интерпретации parser есть отдельный debug-режим с повторным
`-d` (`-dd`).

Эти команды приведены как способы проверки; результаты их выполнения в этом
документе не зафиксированы.

## 8. Интеграция с systemd

Многие сервисы уже имеют профили в `/etc/apparmor.d/`. Проверь каталог:

```bash
ls -la /etc/apparmor.d/
```

Для сервисов перезагрузи AppArmor:

```bash
systemctl reload apparmor
```

## 9. Rollback и восстановление

Если профиль блокирует приложение, переведи его в Complain через
`aa-complain <profile>`. Затем исправь или временно отключи только проблемный
профиль, не затрагивая остальные. После правки повторно загрузи профиль через
`apparmor_parser -r /path/to/profile` либо перезагрузи сервис командой
`systemctl reload apparmor`, после чего снова проверь статус и журнал.
