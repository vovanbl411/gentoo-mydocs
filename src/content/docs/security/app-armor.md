AppArmor — система Mandatory Access Control (MAC), которая ограничивает
приложения профилями с разрешениями на доступ к файлам, возможностям и другим
ресурсам. Это руководство показывает базовую настройку AppArmor, режимы и
управление профилями, создание своего профиля и диагностику нарушений.

Это общее руководство, оно не описывает подтверждённое состояние ASUS B5402.
Приведённые параметры ядра и загрузки — существующие примеры из документа, а
не зафиксированная конфигурация эталонной системы.

## 1. Перед включением

До изменения системы нужны:

- поддержка AppArmor и audit в ядре;
- userspace-пакеты AppArmor;
- корректные параметры загрузки;
- понимание того, что профиль в режиме Enforce может блокировать действия
  приложения, если нужные разрешения не описаны.

### Поддержка в ядре

В существующем примере конфигурации ядра включены следующие опции:

```conf
CONFIG_SECURITY_APPARMOR=y
CONFIG_SECURITY_APPARMOR_BOOTPARAM_VALUE=1
CONFIG_AUDIT=y
```

Существующий пример параметров загрузки (CMDLINE):

```text
security=apparmor lsm=landlock,bpf,apparmor
```

Эти значения во время редакторской миграции не проверялись и не подтверждают
текущую конфигурацию ASUS B5402.

## 2. Установка и включение

Установи userspace-пакеты:

```bash
emerge -av sys-apps/apparmor sys-apps/apparmor-utils
```

Включи и запусти сервис:

```bash
doas systemctl enable apparmor
doas systemctl start apparmor
```

## 3. Режимы и управление профилями

Профиль AppArmor может работать в одном из трёх режимов:

- **Enforce** — активная защита, блокирует нарушения;
- **Complain** — только логирует нарушения, не блокирует;
- **Disable** — профиль отключён.

### Основные команды

| Команда | Описание |
|---------|----------|
| `apparmor_status` | Показать статус AppArmor |
| `aa-status` | Краткий статус профилей |
| `aa-complain <profile>` | Перевести профиль в режим complain |
| `aa-enforce <profile>` | Перевести профиль в режим enforce |
| `apparmor_parser -r /path/to/profile` | Перезагрузить профиль |

Перед переводом нового или изменённого профиля в Enforce проверь поведение
приложения в Complain: так потенциально недостающие разрешения сначала
появятся в журнале, а не заблокируют приложение.

## 4. Создание и обновление профиля

### 4.1. Перевод приложения в Complain

```bash
doas aa-complain /usr/bin/application
```

### 4.2. Использование приложения

Запусти приложение и выполни типичные операции, чтобы AppArmor записал
обращения к нужным ресурсам.

### 4.3. Генерация профиля

```bash
doas aa-genprof /usr/bin/application
```

Следуй интерактивному wizard для настройки правил. После изменения профиля
перезагрузи его командой `apparmor_parser -r /path/to/profile` из таблицы
выше. Режим можно менять через `aa-complain` и `aa-enforce`.

## 5. Пример профиля

Ниже сохранён существующий пример профиля. Во время структурной миграции его
синтаксис и семантика не проверялись.

```apparmor
#include <tunables/global>
/usr/bin/example {
  #include <abstractions/base>

  # Файлы
  /etc/example/** r,
  /var/lib/example/ rw,
  /home/*/.config/example/** rw,

  # Возможности
  capability net_bind_service,

  # Сеть
  network inet stream,

  # Окружение
  environment /etc/example/env,
}
```

## 6. Утилиты

- **aa-notify** — уведомления о нарушениях;
- **logprof** — анализ логов и обновление профилей;
- **genprof** — генерация профиля на основе использования.

## 7. Проверка и диагностика

Состояние AppArmor и загруженных профилей показывают `apparmor_status` и
`aa-status` из таблицы основных команд. Для диагностики нарушений и проверки
конкретного профиля используй существующие примеры:

```bash
# Просмотр логов нарушений
dmesg | grep -i apparmor

# Или через journalctl
journalctl -b | grep -i apparmor

# Детальный анализ
apparmor_parser -d /etc/apparmor.d/profile.name
```

Эти команды приведены как способы проверки; результаты их выполнения в этом
документе не зафиксированы.

## 8. Интеграция с systemd

Многие сервисы уже имеют профили в `/etc/apparmor.d/`. Проверь каталог:

```bash
ls -la /etc/apparmor.d/
```

Для сервисов перезагрузи AppArmor:

```bash
systemctl reload apparmor
```

## 9. Rollback и восстановление

Если профиль блокирует приложение, переведи его в Complain через
`aa-complain <profile>`. Затем исправь или временно отключи только проблемный
профиль, не затрагивая остальные. После правки повторно загрузи профиль через
`apparmor_parser -r /path/to/profile` либо перезагрузи сервис командой
`systemctl reload apparmor`, после чего снова проверь статус и журнал.
