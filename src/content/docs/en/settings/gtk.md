The specific ASUS B5402 configuration is recorded in the
[system document](../../systems/asus-b5402/desktop/environment/). This guide
describes a symptom observed on the verified machine; it does not explain all
GTK theme problems.

## Symptom

GTK4 applications may not receive the Noctalia palette, may show a transparent
or incorrect background, and GTK4 and libadwaita applications may respond to
the theme differently.

## Cause on the verified system

On the verified machine, the problem was related to broken or local theme
imports, a mix of the system theme and `~/.config/gtk-4.0/`, and differences
between GTK4 and libadwaita applications. This is not a universal cause of GTK
problems.

## Working configuration

The final setup uses a local CSS file to import the palette generated by
Noctalia:

```text
~/.config/gtk-4.0/
├── gtk.css
├── noctalia.css
└── settings.ini
```

```text
Noctalia generates palette
→ local GTK CSS imports it
→ application consumes resulting GTK colors/styles
```

GTK4 automatically reads `$XDG_CONFIG_HOME/gtk-4.0/gtk.css`. This file imports
the generated `noctalia.css` palette and contains selectors for widgets that
need more than the palette alone:

File: `~/.config/gtk-4.0/gtk.css`

```css
@import url("noctalia.css");

/* Extra rules are needed only for widgets that the palette alone does not cover. */
window {
  background-color: @window_bg_color;
  color: @window_fg_color;
}

headerbar, .titlebar {
  background-color: @headerbar_bg_color;
  color: @headerbar_fg_color;
}

button {
  background-color: @card_bg_color;
  color: @card_fg_color;
}

button:checked, button:active {
  background-color: @accent_bg_color;
  color: @accent_fg_color;
}

scale trough {
  background-color: @card_bg_color;
}

scale highlight, scale slider {
  background-color: @accent_bg_color;
}
```

File: `~/.config/gtk-4.0/settings.ini`

```ini
[Settings]
gtk-application-prefer-dark-theme=1
```

## Apply the fix

### Check imports first

Check that the local files exist and that the `noctalia.css` import resolves:

```bash
ls -la ~/.config/gtk-4.0/
```

If `gtk.css` is an old symlink to a system theme, replace it with the local
file shown above. Do not add `@import url("noctalia.css")` to
`/usr/share/themes/...`: a system theme must not depend on a palette in `$HOME`.

### Repair a system theme only when needed

Do not remove `/usr/share/themes/...` as a first step. First establish that the
affected files are system-owned: check their owner and package integrity with
an available tool, such as `equery check <category/package>`. If the check
confirms damage, reinstall the package through the normal Portage workflow and
check that its CSS files were restored.

Manual removal from `/usr/share/themes/...` is appropriate only for proven
leftovers that Portage did not restore after reinstallation. Before removing
anything, record the exact path and reason so files belonging to another
package are not deleted.

### Refresh palette and local CSS

After changing the palette, regenerate `noctalia.css` with Noctalia and restart
the application. To rule out stale local state, clear the GTK4 cache only after
checking the directory contents:

```bash
rm -rf ~/.cache/gtk-4.0/
```

## GTK4 vs libadwaita

GTK4 and libadwaita theming differ substantially from GTK3. Custom CSS in
`~/.config/gtk-4.0/` applies independently of the older GTK3 theme model;
`gtk-theme-name` should not be treated as the only way to style GTK4.
libadwaita applications may deliberately limit traditional custom themes. So
custom CSS is a local solution for specific widgets, not a universal official
mechanism for theming every application.

If the palette definitions do not produce the desired result in a plain GTK4
application, add selectors only for the widget you observed. For example, the
`scale` rules above are for sliders, not the entire theme.

## Verification

Check that:

- `gtk.css` imports an available `noctalia.css`;
- the application starts without CSS warnings or errors;
- the background, foreground, and selected state look correct;
- after regeneration, the application reflects the new Noctalia palette.

## Diagnostics

These commands launch an application for diagnostics only; do not use
`GTK_THEME` or `GTK_DEBUG` as persistent configuration.

```bash
# GTK4 version
pkg-config --modversion gtk4

# Application dependencies
ldd "$(command -v <application>)" | grep -E "gtk-4|adwaita"

# GTK Inspector
GTK_DEBUG=interactive <application>

# Launch from a terminal to see CSS parsing warnings
<application>

# Temporary launch without a theme or with an explicit GTK3 theme
GTK_THEME= <application> &
GTK_THEME=adw-gtk3-dark <application> &
```

## Example palette

The full `noctalia.css` is not duplicated here: Noctalia generates it, and the
values change with the palette. A minimal illustrative fragment is:

```css
@define-color window_bg_color #0b0e14;
@define-color window_fg_color #d1d1c7;
@define-color accent_bg_color #e6b450;
@define-color accent_fg_color #0b0e14;
```
