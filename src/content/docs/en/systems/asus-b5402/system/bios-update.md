## Current state

- BIOS `B5402CBA.314` is installed through ASUS Firmware Update/EZ Flash.
- Secure Boot is enabled with custom `sbctl` keys; Setup Mode is disabled.
- The root filesystem uses LUKS2 with TPM2 integration.
- Boot uses systemd-boot and UKIs generated by Dracut. See [Boot and Portage](../boot-and-portage/).

## Before the update

### Check the model and BIOS version

Confirm that the system reports the ASUS ExpertBook B5402CBA model and check
its current BIOS version:

```bash
cat /sys/class/dmi/id/product_name
cat /sys/class/dmi/id/bios_version
```

### Check the LUKS passphrase

Before changing Secure Boot, manually verify the passphrase or recovery key for
root LUKS. First identify the root mapper and its backing device:

```bash
findmnt -no SOURCE,FSTYPE /
lsblk -o NAME,TYPE,FSTYPE,SIZE,MOUNTPOINTS
ROOT_MAPPER="REPLACE_WITH_ROOT_MAPPER_NAME"
doas cryptsetup status "$ROOT_MAPPER"
```

The `device:` field in `cryptsetup status` shows the backing LUKS device. Set
that path in the next command and enter the secret only at cryptsetup's prompt:

```bash
ROOT_LUKS_DEVICE="REPLACE_WITH_ROOT_LUKS_DEVICE"
doas cryptsetup open --test-passphrase "$ROOT_LUKS_DEVICE"
```

The command must exit with code `0`. Run this check manually immediately
before the update; do not store the passphrase or recovery key in the
repository.

### Check the power supply

Connect AC power and make sure the battery charge is at least 20%, as required by ASUS for EZ Flash.

## Verify the firmware image

Download the firmware only from the [official ASUS support page for
B5402CBA](https://www.asus.com/us/supportonly/b5402cba/helpdesk_bios/). Choose
**BIOS for ASUS EZ Flash Utility**, not the Windows installer.

Set the archive path and verify it. Compare the SHA-256 output with the value
ASUS publishes for the selected version:

```bash
BIOS_ZIP="$HOME/Downloads/REPLACE_WITH_ASUS_EZ_FLASH_ARCHIVE.zip"
sha256sum "$BIOS_ZIP"
unzip -t "$BIOS_ZIP"
unzip -l "$BIOS_ZIP"
```

Confirm that the archive is valid and contains a firmware image for model
`B5402CBA`. Use the filename and archive listing to select the image intended
for ASUS EZ Flash.

## Prepare the USB drive

ASUS EZ Flash needs a FAT32 partition. ASUS does not require a particular USB
layout, including Ventoy. Device names can change, so identify the partition
again by size, filesystem, and label before mounting it:

```bash
lsblk -o NAME,SIZE,FSTYPE,LABEL,MOUNTPOINTS,RO,RM
```

Set the FAT32 partition and the firmware image filename from the archive, then
extract the image to a temporary directory. Run these commands in the same
shell session so the variables remain set:

```bash
USB_FAT32_DEVICE="/dev/REPLACE_WITH_FAT32_PARTITION"
BIOS_FILE="REPLACE_WITH_FIRMWARE_IMAGE_FILENAME"
BIOS_DIR="$(mktemp -d)"

unzip -j "$BIOS_ZIP" "$BIOS_FILE" -d "$BIOS_DIR"
```

Mount the identified partition. Check the `findmnt` output for the source
device, FAT32 (`vfat`), and the `rw` option:

```bash
doas mkdir -p /mnt/bios-usb
doas mount -o rw,nosuid,nodev,noexec,uid=$(id -u),gid=$(id -g),umask=022 \
  "$USB_FAT32_DEVICE" /mnt/bios-usb
findmnt -no SOURCE,FSTYPE,OPTIONS /mnt/bios-usb
```

Copy the image and compare the source with the copy. `cmp` must report no
differences; then unmount the partition:

```bash
cp "$BIOS_DIR/$BIOS_FILE" /mnt/bios-usb/
sync -f /mnt/bios-usb
cmp "$BIOS_DIR/$BIOS_FILE" "/mnt/bios-usb/$BIOS_FILE"
doas umount /mnt/bios-usb
```

## Update the BIOS

On this workstation, ASUS Firmware Update rejected a known-good official image
while Secure Boot with custom `sbctl` keys was enabled. After only Secure Boot
was temporarily disabled, the same verified image was accepted. This
observation applies to this machine; it does not establish the firmware's
internal reason and is not a general ASUS rule.

1. Enter UEFI by pressing `F2`.
2. If ASUS Firmware Update rejects the verified image while Secure Boot is
   enabled, temporarily disable Secure Boot only. Save the change, reboot, and
   re-enter UEFI by pressing `F2`.
3. Do not clear the TPM, PK, KEK, `db`, or `dbx`. Do not load UEFI defaults.
4. Open ASUS Firmware Update / EZ Flash and select the verified image on the
   FAT32 partition.
5. Confirm the update and do not disconnect power until it completes and
   reboots.
6. After the update, restore Secure Boot to its original enabled state and boot
   Gentoo.

## Verify after the update

After booting, check the BIOS version, Secure Boot state, and TPM2 availability:

```bash
cat /sys/class/dmi/id/bios_version
cat /sys/class/dmi/id/bios_date
sbctl status
systemd-cryptenroll --tpm2-device=list
systemctl --failed
```

Expected results:

- The BIOS version matches the selected image.
- Secure Boot is enabled and Setup Mode is disabled.
- TPM2 is available to the system.
- Gentoo booted normally using the expected LUKS2/TPM2 root-unlock path.
- No new failed units related to the update are present.

## Recovery

- If TPM2 unlocking fails, use the LUKS passphrase or recovery key verified in advance.
- If Secure Boot rejects the UKI, temporarily disable it, boot the system, and
  check keys and signatures with `sbctl`.
- Do not clear the TPM, PK, KEK, `db`, or `dbx` as the first recovery step.
