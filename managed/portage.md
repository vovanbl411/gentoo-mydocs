# Руководство по управлению Gentoo Linux

## 1. Основы Portage и emerge

**Portage** – это система управления пакетами, состоящая из:

- **Дерева портежей** (ebuild-репозитория) – коллекции скриптов (ebuild’ов), описывающих, как собрать и установить каждый пакет.

- **Инструментария** – в первую очередь команды `emerge`, а также вспомогательные утилиты.

### 1.1. Основные команды emerge

| Действие | Команда | Пояснение |
|----------|---------|-----------|
| Установка пакета | `emerge <package>` | Собирает и устанавливает пакет с зависимостями. |
| Поиск пакета | `emerge -s <keyword>` | Ищет пакеты по имени и описанию (устаревший метод, лучше использовать `eix`). |
| Удаление пакета | `emerge --deselect <package>` (или `--depclean` после) | Помечает пакет как не входящий в @world, затем `emerge --depclean` удалит его, если он не нужен как зависимость. Для полного удаления с зависимостями: `emerge -c <package>` (осторожно!). |
| Обновление дерева портежей | `emerge --sync` | Синхронизирует локальный репозиторий с официальным (или зеркалом). |
| Показать зависимости | `emerge -p <package>` | Показывает, что будет установлено/обновлено (pretend). |
| Подробный вывод | `emerge -v <package>` | Включает подробный режим (verbose). |
| Спросить подтверждение | `emerge -a <package>` | Запрашивает подтверждение перед действием (ask). |

**Пример установки пакета с интерактивным подтверждением:**

```bash
emerge -av app-text/evince
```

### 1.2. Важные опции emerge

- `-u` – обновить пакет до последней доступной версии.
- `-D` – углублённое обновление зависимостей (deep).
- `-N` – изменить USE-флаги в соответствии с новыми настройками (newuse).
- `--with-bdeps=y` – включает зависимости, нужные только на этапе сборки (обычно не включаются в @world).
- `--keep-going` – продолжать, даже если некоторые пакеты не собираются.
- `--jobs=JOBS` и `--load-average` – параллельная сборка.

## 2. Управление USE-флагами

USE-флаги определяют, с какой поддержкой функций собирать пакеты (например, `ssl`, `gtk`, `pulseaudio`). Они управляются в файлах конфигурации.

### 2.1. Глобальные настройки – `/etc/portage/make.conf`

Пример:

```bash
USE="X gtk gnome -kde -qt5"
CFLAGS="-march=native -O2 -pipe"
MAKEOPTS="-j4"
ACCEPT_KEYWORDS="amd64"
```

- `USE` – список флагов (знак `-` отключает флаг).
- `ACCEPT_KEYWORDS` – "amd64" для стабильных пакетов, "~amd64" для тестовых.

### 2.2. Постоянные USE-флаги для отдельных пакетов

Файлы в `/etc/portage/package.use/` (может быть директория или файл). Например, для пакета `www-client/firefox` включить `hwaccel` и отключить `pulseaudio`:

```bash
www-client/firefox hwaccel -pulseaudio
```

### 2.3. Просмотр текущих USE-флагов

- Для конкретного пакета: `equery uses <package>` или `emerge -pv <package>`.
- Глобально: `portageq envvar USE`.

### 2.4. Изменение USE и пересборка

После изменения USE-флагов необходимо пересобрать пакеты, чтобы изменения вступили в силу:

```bash
emerge -uDN @world
```

Флаг `-N` (`--newuse`) заставит пересобрать пакеты, у которых изменились USE-флаги.

## 3. Работа с зависимостями и разрешение конфликтов

### 3.1. Понимание зависимостей

- **DEPEND** – зависимости сборки.
- **RDEPEND** – зависимости времени выполнения.
- **PDEPEND** – зависимости, которые должны быть установлены после.

Portage автоматически разрешает зависимости, но иногда возникают конфликты (блокировки). Типичные ситуации:

- **Блокировка слот/подслот** – когда два пакета не могут сосуществовать. Решается обновлением или маской.
- **Циклические зависимости** – редко, но бывают. Можно разрешить, временно установив один пакет вручную с игнорированием зависимостей (`--nodeps`) – но осторожно.

### 3.2. Команды для анализа зависимостей

- `emerge -p --depclean` – показать, какие пакеты будут удалены как неиспользуемые.
- `equery depends <package>` – показывает, какие пакеты зависят от данного.
- `equery depgraph <package>` – строит граф зависимостей.
- `eix-test-obsolete` – проверяет устаревшие пакеты (требует eix).

### 3.3. Решение блокировок

Часто блокировки возникают из-за необходимости обновить Portage или изменить USE. Рекомендуется:

1. Выполнить `emerge --sync`.
2. Попробовать `emerge -uDN @world`.
3. Если конфликт не решается, можно временно замаскировать проблемный пакет (`/etc/portage/package.mask`) или использовать `--backtrack=30` для углублённого поиска решений.

## 4. Поиск пакетов: eix и equery

Традиционный `emerge -s` устарел и неудобен. Рекомендуется использовать **eix** – быстрый индексатор дерева портежей.

### 4.1. Установка eix

```bash
emerge -av app-portage/eix
```

После установки необходимо обновить индекс:

```bash
eix-update
```

### 4.2. Основные команды eix

| Команда | Описание |
|---------|----------|
| `eix <package>` | Поиск пакета по точному имени или части имени. |
| `eix -S <keyword>` | Поиск по описанию (slow, но тщательный). |
| `eix -I` | Показать только установленные пакеты. |
| `eix -c` | Показать только пакеты в нестабильной версии (~). |
| `eix --only-names` | Вывести только имена пакетов. |

Пример: найти все пакеты, связанные с python:

```bash
eix -S python
```

### 4.3. eix-test-obsolete – поиск устаревших пакетов

Утилита `eix-test-obsolete` (входит в пакет eix) помогает обнаружить пакеты, которые больше не находятся в дереве портежей (например, устаревшие, перемещённые или удалённые), а также пакеты, для которых доступны более новые версии, но они не установлены. Это полезно для очистки системы от мёртвого груза.

Запуск:

```bash
eix-test-obsolete
```

Вывод покажет:

- пакеты, которых больше нет в дереве (obsolete);
- пакеты, для которых есть более новые версии (upgradable);
- пакеты, которые были перемещены в другую категорию (moved).

После анализа можно принять решение: удалить устаревшие пакеты (например, через `emerge --deselect` + `--depclean`) или обновить.

### 4.4. equery – мощный инструмент для анализа

Устанавливается как часть `app-portage/gentoolkit`.

```bash
emerge -av app-portage/gentoolkit
```

Основные команды equery:

| Команда | Описание |
|---------|----------|
| `equery list <package>` | Показывает установленные версии. |
| `equery files <package>` | Список файлов, установленных пакетом. |
| `equery depends <package>` | Какие пакеты зависят от данного. |
| `equery which <package>` | Путь к ebuild-файлу. |
| `equery size <package>` | Размер установленных файлов. |
| `equery uses <package>` | Показывает USE-флаги пакета и их статус. |
| `equery check <package>` | Проверяет целостность установленных файлов. |
| `equery graph <package>` | Генерирует граф зависимостей (в виде ascii). |

Пример: посмотреть USE-флаги firefox:

```bash
equery uses www-client/firefox
```

## 5. Обновление системы

### 5.1. Синхронизация дерева портежей

```bash
emerge --sync
```

Или для более быстрой синхронизации с использованием git (рекомендуется):

```bash
emerge --sync --quiet
```

Настройки синхронизации в `/etc/portage/repos.conf`.

### 5.2. Обновление мира (всех пакетов)

Стандартная команда для полного обновления системы:

```bash
emerge -avuDN @world
```

Разбор опций:

- `-a` (--ask) – запросить подтверждение перед выполнением действий.
- `-v` (--verbose) – показать подробную информацию о планируемых изменениях.
- `-u` (--update) – обновить пакеты до последней доступной версии.
- `-D` (--deep) – углублённое обновление, проверяет зависимости не только первого уровня, но и всю цепочку; гарантирует, что все зависимости будут актуальны.
- `-N` (--newuse) – пересобрать пакеты, у которых изменились USE-флаги (например, после правки make.conf или package.use).
- `@world` – целевой набор, включающий все явно установленные пакеты и их зависимости.

Для безопасности сначала посмотрите, что будет сделано:

```bash
emerge -uDNp @world   # p = pretend
```

### 5.3. Обновление Portage

Portage обновляется как обычный пакет, но иногда требуются особые шаги. Рекомендуется сначала обновить Portage:

```bash
emerge -uav sys-apps/portage
```

### 5.4. Работа с конфигурационными файлами

После обновления могут появиться новые конфигурационные файлы (с суффиксом `._cfg0000_...`). Их нужно объединить с существующими. Для этого используются инструменты:

- **dispatch-conf** (рекомендуется) – интерактивное слияние.
- **etc-update** – более простой, но менее гибкий.
- **conf-update** – из пакета app-portage/portage-utils.

Пример с dispatch-conf:

```bash
dispatch-conf
```

Он покажет различия и предложит варианты действий.

## 6. Очистка системы от мусора

### 6.1. Удаление неиспользуемых пакетов

Пакеты, которые не требуются ни одному из установленных пакетов (сироты), можно удалить с помощью `--depclean`:

```bash
emerge --depclean
```

Рекомендуется сначала посмотреть, что будет удалено:

```bash
emerge -p --depclean
```

```bash
emerge --ask --depclean --verbose net-vpn/tailscale
```

Если вы случайно удалили нужный пакет, его можно вернуть, просто установив заново.

### 6.2. Пересборка сломанных зависимостей

Иногда после обновления некоторые библиотеки меняют ABI, и программы, собранные против старых версий, перестают работать. Инструмент `revdep-rebuild` (из пакета `app-portage/gentoolkit`) перестраивает такие пакеты:

```bash
revdep-rebuild
```

Можно запускать с опцией `-p` для предварительного просмотра.

### 6.3. Очистка исходных кодов

Portage хранит скачанные исходники в `/usr/portage/distfiles` (или `/var/cache/distfiles`). Со временем они занимают много места. Для их очистки используйте `eclean-dist` (из пакета `app-portage/gentoolkit`):

```bash
eclean-dist
```

Можно также удалить устаревшие бинарные пакеты:

```bash
eclean-pkg
```

### 6.4. Очистка старых версий ядра

При установке новых ядер старые остаются в `/boot`. Для их удаления используйте `eclean-kernel` (из пакета `app-portage/gentoolkit`):

```bash
eclean-kernel -n 2   # оставить последние 2 ядра
```

## 7. Работа с оверлеями

Оверлеи – дополнительные репозитории ebuild'ов, не входящие в официальное дерево. Для управления оверлеями используется `eselect repository` (заменяет layman).

### 7.1. Установка eselect repository

```bash
emerge -av app-eselect/eselect-repository
```

### 7.2. Основные команды

- Список доступных оверлеев: `eselect repository list`
- Добавить оверлей: `eselect repository enable <имя>`
- Добавить сторонний оверлей (например, из git): `eselect repository add <имя> <тип> <url>`
- Синхронизировать все оверлеи: `emerge --sync`

Пример добавления популярного оверлея `guru`:

```bash
eselect repository enable guru
emerge --sync guru
```

### 7.3. Установка пакетов из оверлея

После синхронизации пакеты становятся доступны как обычные. Иногда нужно указать категорию.

## 8. Управление ядром

Gentoo даёт полный контроль над ядром. Существует несколько подходов: ручная настройка, использование `genkernel`, а также современный метод с `installkernel` и `dracut`.

### 8.1. Ручная сборка

1. Установить исходники ядра: `emerge -av sys-kernel/gentoo-sources`
2. Перейти в каталог: `cd /usr/src/linux`
3. Настроить: `make menuconfig` (или `nconfig`, `xconfig`)
4. Собрать и установить модули: `make && make modules_install`
5. Установить ядро и System.map: `make install`
6. Обновить загрузчик (например, `grub-mkconfig -o /boot/grub/grub.cfg`).

### 8.2. Использование genkernel

Genkernel автоматизирует процесс, создавая ядро с поддержкой большинства устройств (как в дистрибутивах общего назначения).

```bash
emerge -av sys-kernel/genkernel
genkernel all
```

После этого обновить загрузчик.

### 8.3. Современный подход: installkernel + dracut

В последние годы в Gentoo активно развиваются инструменты, упрощающие установку ядра и создание initramfs. installkernel отвечает за копирование образа ядра, System.map и, при необходимости, генерацию конфигурации загрузчика. dracut используется для создания initramfs (вместо устаревшего `genkernel --ramdisk`).

Установка:

```bash
emerge -av sys-kernel/installkernel sys-kernel/dracut
```

Настройка:
В `/etc/portage/make.conf` можно определить предпочтительный способ установки ядра. Например, для автоматического обновления загрузчика GRUB:

```bash
# Использовать installkernel с поддержкой grub
INSTALLKERNEL_OPTS="--grub"
```

Для создания initramfs с помощью dracut при установке ядра через make install необходимо настроить installkernel на вызов dracut. В файле `/etc/installkernel.conf` (или через переменные окружения) укажите:

```bash
# Использовать dracut для создания initramfs
INITRD_GENERATOR=dracut
```

Или передавайте опции через INSTALLKERNEL_OPTS.

Процесс сборки и установки ядра с использованием dracut:

- Настройка ядра (как обычно): make menuconfig
- Сборка: make
- Установка модулей: make modules_install
- Установка ядра и создание initramfs одной командой:

```bash
make install
```

>При этом installkernel скопирует ядро в /boot, создаст initramfs с помощью dracut (если настроено) и обновит загрузчик (если указано `--grub`).

Преимущества:

- Разделение ответственности: installkernel занимается установкой, dracut – initramfs.
- Гибкость настройки initramfs через конфигурационные файлы dracut.
- Поддержка различных загрузчиков (GRUB, systemd-boot, efibootmgr и др.) через плагины installkernel.

### 8.4. Модули ядра

Модули, которые должны загружаться автоматически, перечисляются в `/etc/conf.d/modules`.

## 9. Продвинутые темы

### 9.1. Использование ccache для ускорения пересборок

ccache кэширует результаты компиляции, что ускоряет повторные сборки.

```bash
emerge -av dev-util/ccache
```

В `/etc/portage/make.conf` добавить:

```bash
FEATURES="ccache"
CCACHE_SIZE="2G"
```

### 9.2. Распределённая компиляция с distcc

Позволяет задействовать несколько машин для сборки.

```bash
emerge -av sys-devel/distcc
```

Настройка в `/etc/portage/make.conf`:

```bash
FEATURES="distcc"
MAKEOPTS="-jN"   # N = общее количество потоков всех машин
```

### 9.3. Бинарные пакеты (binhost)

Можно настроить локальный или удалённый репозиторий бинарных пакетов для быстрой установки без компиляции. Подробнее в [Gentoo Wiki: Binary package guide](https://wiki.gentoo.org/wiki/Binary_package_guide).

### 9.4. Проверка безопасности – glsa-check

Gentoo публикует уведомления о безопасности (GLSA). Проверить систему на наличие уязвимых пакетов:

```bash
glsa-check -l           # список всех GLSА
glsa-check -t all       # проверить систему
glsa-check -f all       # применить обновления (после проверки)
```

Утилита входит в `gentoolkit`.

## 10. Часто задаваемые вопросы и решение проблем

### 10.1. Ошибка "blocked packages"

Означает, что два пакета не могут быть установлены одновременно. Часто решается обновлением мира или маскировкой одного из пакетов. Иногда помогает `--backtrack=30`.

### 10.2. Ошибка "use flag changes"

При выполнении `emerge -uDN @world` появляется предупреждение о необходимости изменить USE. Просто запустите с флагом `-N` или `--newuse`.

### 10.3. Не собирается пакет из-за нехватки памяти

Увеличьте раздел подкачки или используйте `--jobs=1` для последовательной сборки.

### 10.4. Как восстановить сломанную систему?

Если система не загружается, можно загрузиться с LiveCD, примонтировать разделы и выполнить `emerge -uDN @world` из chroot. Или использовать инструменты восстановления, такие как `gentoo-rescue`.

## 11. Заключение

Gentoo предоставляет уникальную гибкость, но требует понимания происходящего. Регулярное обслуживание – залог стабильности. Помните:

- Всегда делайте резервное копирование важных данных.
- Перед крупными обновлениями читайте новости Gentoo (`eselect news list`).
- Используйте `--pretend` и `--ask`, чтобы избежать сюрпризов.
- Обращайтесь к [Gentoo Wiki](https://wiki.gentoo.org/) и сообществу за помощью.
