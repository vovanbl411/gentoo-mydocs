# Настройка Snapper (Snapshots)

Snapper управляет снимками корневого субволюма `@`. Это позволяет откатить систему к любому предыдущему состоянию (целиком или пофайлово).

## 1. Конфигурация и права

Используется конфиг `root` для точки монтирования `/`.

Доступ без root:

Для управления снимками от обычного пользователя (группа wheel) в `/etc/snapper/configs/root` заданы:

- `ALLOW_GROUPS="wheel"`
- `SYNC_ACL="yes"`

После правок конфига права применяются командой:

```bash
doas snapper -c root setup-acl
```

## 2. Автоматизация в Gentoo (Portage)

Для интеграции с пакетным менеджером используется хук в `/etc/portage/bashrc`. При каждом `emerge` создается пара снимков типа Pre и Post.

> **Примечание**: Снимки с описанием "Before emerge..." и "After emerge..." связаны между собой ID, что позволяет видеть разницу, внесенную конкретным пакетом.

## 3. Политика очистки (Cleanup)

Чтобы снимки не заняли всё место на NVMe, настроены следующие лимиты:

- **Timeline (Часовые)**: Храним 5 последних часов и 7 последних дней. Еженедельные и ежемесячные снимки практически отключены (1 и 0), чтобы минимизировать хранение старых данных.
- **Number (Portage)**: Храним последние 10 пар снимков обновлений.
- **Space Limit**: Если диск заполнен более чем на 80% (`SPACE_LIMIT="0.8"`), алгоритм очистки начнет удалять старые снимки агрессивнее.

## 4. Шпаргалка по использованию

### Просмотр истории

```bash
snapper list
```

### Анализ изменений

```bash
# Посмотреть разницу в файлах между снимками 15 и 16
snapper status 15..16

# Посмотреть конкретные изменения в коде (diff)
snapper diff 15..16 /etc/conf.d/net
```

### Откат (Undo)

```bash
# Откатить изменения, внесенные установкой пакета (между pre и post)
snapper undochange 15..16

# Восстановить один случайно удаленный файл из снимка №10
snapper restore -s 10 /etc/fstab
```

## 5. Обслуживание системы (Systemd)

Для автоматического управления снимками должны быть активны следующие таймеры:

- **snapper-timeline.timer**: Создает ежечасные снимки.
- **snapper-cleanup.timer**: Раз в час запускает скрипт очистки старых снимков согласно лимитам из конфига.
- **snapper-boot.timer** (опционально): Создает снимок при каждой загрузке системы.

Команды для проверки и управления:

```bash
# Проверить статус всех таймеров snapper
systemctl status "snapper-*.timer"

# Посмотреть, когда сработают следующие таймеры
systemctl list-timers "snapper-*"

# Принудительно запустить цикл очистки
doas systemctl start snapper-cleanup.service
```

### Мониторинг места

Так как мы используем Btrfs, обычный `df` может немного привирать. Для контроля за тем, сколько места «съедают» именно снапшоты, используй:

```bash
doas btrfs filesystem du -s /.snapshots
```

> **Примечание**: Сервисы в порядке. snapperd засыпает и просыпается по требованию (через D-Bus) — это нормальное поведение (static/inactive).
