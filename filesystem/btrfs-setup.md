# Структура Btrfs и субволюмы

В системе используется Btrfs с разделением на субволюмы. Это позволяет гибко управлять снимками (snapshots) и исключать временные файлы из бэкапов.

## 1. Иерархия субволюмов

Для корректной работы откатов и чистоты системы используется плоская структура (Flat Layout):

- `@` — корень системы (`/`)
- `@home` — пользовательские данные (`/home`)
- `@snapshots` — место хранения снимков Snapper (`/.snapshots`)
- `@var_log` — логи (исключены из снимков) (`/var/log`)
- `@var_cache` — системный кэш (`/var/cache`)
- `@distfiles` — исходные коды скачанных пакетов (`/var/cache/distfiles`)
- `@ccache` — кэш компилятора C/C++ (`/var/tmp/ccache`)
- `@portage_tree` — дерево портажей (`/var/db/repos/gentoo`)
- `@docker` — данные контейнеров Docker (`/var/lib/docker`)
- `@libvirt` — образы виртуальных машин KVM/Qemu (`/var/lib/libvirt`)
- `@portage_tmp` — рабочая директория для тяжелых сборок (`/var/tmp/portage-disk`)

## 2. Опции монтирования

В `/etc/fstab` используются следующие параметры для оптимизации на NVMe (Alder Lake):

- **ssd**: Оптимизация под твердотельные накопители.
- **compress=zstd:3**: Прозрачное сжатие (баланс скорости и экономии места).
- **noatime**: Отключение записи времени последнего доступа для снижения нагрузки на диск.
- **discard=async**: Фоновая очистка неиспользуемых блоков (TRIM).

## 3. Оптимизация сборки (tmpfs)

Для минимального износа SSD и максимального ускорения компиляции пакетов, основная рабочая директория Portage вынесена в оперативную память:

- `/var/tmp/portage` — смонтирована как tmpfs (16 Gb)

## 4. Очистка и балансировка

Чтобы Btrfs не деградировала по производительности:

- **Scrub**: Проверка целостности данных раз в месяц.
- **Balance**: Перераспределение данных (актуально, если диск заполнен более чем на 80%).

### Проверка состояния

```bash
# Просмотр статистики ошибок устройства
doas btrfs device stats /

# Запуск фоновой проверки целостности
doas btrfs scrub start /

# Проверка статуса запущенного scrub
doas btrfs scrub status
```

## 5. Нюансы BTRFS

Btrfs — это механизм Copy-on-Write (CoW).

Btrfs по умолчанию использует CoW (запись при копировании) для всех данных. Это здорово для снапшотов и защиты от повреждений, но для файлов, которые постоянно перезаписываются мелкими блоками (базы данных, образы виртуальных машин, временные файлы компиляции), CoW вызывает чудовищную фрагментацию и сильное падение производительности (особенно IOPS).

Вот что обязательно нужно сделать с этими субволюмами:

1. **@libvirt**: Образы виртуальных машин (`/var/lib/libvirt/images`).
2. **@docker**: Образы и тома баз данных.
3. **@portage_tmp**: Временные файлы компиляции на диске (`/var/tmp/portage-disk`).
4. **@ccache**: Директория `/var/tmp/ccache`. Постоянная перезапись объектных файлов компилятора приводит к деградации производительности на Btrfs без этого атрибута.

## 6. Как правильно отключить CoW (chattr +C)

> **Важное правило Btrfs**: Атрибут `+C` можно применить только к пустым файлам или пустым директориям. Если в директории уже есть файлы, атрибут на них не подействует.

Если директории у тебя сейчас пустые (или ты можешь их очистить), выполни:

```bash
# Для виртуалок
doas chattr +C /var/lib/libvirt/images

# Для временной папки портежей
doas chattr +C /var/tmp/portage-disk

# Для ccache
doas chattr +C /var/tmp/ccache

# Для существующих пустых томов БД в Docker (если есть)
doas chattr +C /var/lib/docker/volumes/my_db_volume/_data
```

> **Примечание**: Установка атрибута `+C` автоматически отключает прозрачное сжатие `compress=zstd` и подсчет контрольных сумм для этих конкретных директорий, что абсолютно правильно для таких типов данных.

### Если в /var/lib/libvirt/images уже лежат образы

Тебе придется создать новую папку, поставить на нее атрибут, перенести туда файлы и переименовать:

```bash
doas mkdir /var/lib/libvirt/images_new
doas chattr +C /var/lib/libvirt/images_new
doas cp -a --reflink=never /var/lib/libvirt/images/* /var/lib/libvirt/images_new/
doas rm -rf /var/lib/libvirt/images
doas mv /var/lib/libvirt/images_new /var/lib/libvirt/images
```
